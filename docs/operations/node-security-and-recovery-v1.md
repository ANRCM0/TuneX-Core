# Node Security & Recovery v1

状态：**Accepted for implementation，尚未实现**。适用于 ADP/2、Node Management 和发布流程。此文定义最小管理行为，不声称已部署 PKI、备份或恢复工具。

## 1. 注册与最小权限

有节点管理权限的用户在明确 scope 下创建 Node 和一次性 enrollment token。token 随机生成、服务端仅保存安全摘要、默认 10 分钟有效且只能成功使用一次；并发兑换通过事务 CAS 保证唯一。注册前必须通过安装配置交付可信 Control CA/公钥 pin 和服务地址，不允许关闭 TLS 校验来完成首次注册。

Agent 在本机生成私钥，通过受信 HTTPS 提交 CSR 与 token；服务端绑定预建 Node ID、scope 和允许的 Agent 身份，签发 node-scoped 凭据。重复网络重试必须能查询同一注册事务结果或安全重新开始，不能再次兑换出第二个身份。token、私钥和恢复凭据不得进入普通日志或前端长期存储。

凭据轮换由当前认证身份发起，新旧凭据重叠期有界；记录 credential ID、NotAfter 和撤销状态。轮换不清空 generation/fence；撤销后拒绝 Hello、Snapshot 续期和业务部署。报告可按明确的审计入口保留，但不能更新当前权威状态。私钥权限仅授予 Agent 运行账号，状态目录使用原子写入、fsync 和完整性保护；保护密钥不得与可任意修改的缓存放在同一不可信权限边界。

## 2. 授权与策略收回

| 授权 | 含义 | 不隐含的权力 |
| --- | --- | --- |
| node.manage | 注册、轮换、撤销该节点 | 不自动授予全部 workspace 用户使用权 |
| node.use | 在授权端口/协议范围创建 Forward | 不允许任意目标网段 |
| forward.manage | 修改本 scope 中明确授权的 Forward | 不绕过 Node/Profile 授权 |
| profile.use | 使用某个不可变 Profile revision | 不允许修改该 revision 的安全要求 |

单用户开发环境也显式创建 scope、owner 与授权，不以省略鉴权模拟单租户。目标网段策略默认拒绝，仅允许显式 CIDR；私有地址/回环可以有意授权，云元数据等敏感目标需独立显式放行。监听默认示例不等于公开访问授权；节点管理需声明允许的监听地址、端口与协议。

收回用户权限阻止其新写操作；收回节点使用授权、目标策略或 Profile 授权时，必须枚举受影响 Forward，持久化撤销/重部署任务、停止续发不再授权的 Assignment，并发布更高 generation。离线 Agent 最迟按既有租约硬截止停流；界面显示 pending revocation 与最晚生效时间，不能宣称即时撤销。改变策略不在相同 configDigest 下偷换含义。

## 3. 重启、重装与双进程

普通重启保留 Node 私钥与 generation/fence/retired 状态，但不直接恢复 socket；先在线 Hello，再应用新快照。丢失或损坏 high-water 的 Agent 停止运行，返回 INTEGRITY_FAILURE，不能当作第一次启动从零接受历史快照。

重装须由管理员退役旧 Node 身份、撤销凭据，等待该身份已签发授权全部到期（加时钟偏差），清理并核实物理主机无旧 Agent/监听，再注册新 Node ID。Forward 重绑新 Node 属于新的用户意图 revision。不得复制旧身份到另一主机并同时运行；本机服务管理器应提供单实例锁，但它不替代服务端会话检查。

新 sessionEpoch 能拒绝旧报告，不能远程证明旧进程已经关闭全部流量。端口复用与删除完成必须计入未过期旧会话，不依赖“新 Agent 已上线”推断旧实例死亡。

## 4. Control/MySQL 旧备份恢复

VNext 初版采用保守停机恢复，不保证恢复旧备份后透明延续 Node 执行身份：

1. 进入维护模式，阻止 API 写入、Worker 发布和租约续期；隔离旧 Control 实例，防止 split-brain 继续签发授权。
2. 使用数据库备份之外保存的可信部署记录确认历史最大授权时长、最后可能签发时间及证书有效边界。自停止全部旧签发端起至少等待该最大时长加允许偏差；若无法证明上界，必须逐节点人工隔离/停止并验证，不猜测“默认 300 秒”。
3. 恢复数据库并检查一致性，只把旧意图作为待审阅数据。旧快照、Operation、观测和幂等记录可能回退，不能据其声称之前的操作从未发生或仍成功。
4. 在独立安全存储中轮换 enrollment/Node 信任材料，关闭旧 Node 身份授权；给 Agent 通过可信管理通道安装新的 Control 信任，退役旧身份并重新注册新 Node ID。不得在同一个 Node ID 下把计数器归零。
5. 审阅恢复的 Forward、删除意图、授权和端口事实，再以新 Node 身份和新 Operation 有意重建；未知状态保持暂停，防止从旧备份复活已撤销规则。幂等历史不完整时要求人工核对，不自动重放外部写请求。
6. 真实验证 TLS、目标策略、端口冲突、TCP/UDP 和旧凭据拒绝后退出维护模式。保留恢复审计、备份时间、影响范围与数据损失说明。

从最新完整备份恢复也必须演练。未来可设计独立 trust epoch 的自动恢复协议，但不得用临时清空 Agent high-water 代替。

## 5. Relay 前置安全门槛

Native 只表示实现驱动，不声明加密。Phase 3 必须冻结：Node 间可达 endpoint（不同于 Control 地址）、内部监听端口分配、对端 Node/Deployment 身份认证、重放防护、TCP stream 与 UDP association 封装、最大帧/数据报、回包映射、关闭/超时与目标 allowlist。

公网跨节点必须使用经审查的加密且相互认证的通道；纯明文实验只能在显式隔离测试环境、显式不安全 Profile 下验收，不能作为默认或生产支持。采用哪种现有传输及版本，由 Phase 3 的专门 ADR 决定。没有 ADR、config/wire Schema 和负面身份测试时，不开始 Relay 功能开发。不得把自定义密码学或未定义的 tst.v1 当已可用能力。

## 6. 发布清单与容量

开发支持基线为 Linux，具体架构/内核、Go/运行时/数据库版本必须在交付记录锁定。生产使用外部 MySQL/Redis 和已有反代时，应提供网络、防火墙、TLS 终止、最小权限、备份、状态目录挂载和健康检查说明。Agent 的低端口能力、文件描述符与内存限制必须显式配置，不默认授予无界 root 权限。

发布前记录单 Node 的 TCP/UDP 并发、内存/fd/goroutine、吞吐与时延、快照大小、续期写入量、全节点重连峰值；指标来自实际环境，不以默认限额推断性能。保留期、快照容量、审计和幂等记录增长需要可观测和告警，不能静默删掉反重放状态。

最低演练：证书轮换/到期、Control 故障超过租约、MySQL 恢复旧备份、Agent 丢失状态、部署版本不兼容、回滚应用二进制但保留持久计数器。回滚不允许降级授权语义；不支持的协议/Schema 必须拒绝启动或拒绝工作。
