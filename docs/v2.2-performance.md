## P3 缓冲区所有权

业务写入先复制到独占 buffer；入队前失败由 `send` 归还。入队后由队列或写循环
归还：RESET、规则关闭及 carrier failure 只回收仍在队列内的帧，已经出队且
正在写出的帧由写循环负责。调用方 deadline/cancel 先返回时不能提前复用。

缓存只保留最多 256 个 16 KiB buffer；满时丢弃。完整 buffer 在归还前清零，
防止较小帧尾部保留其他 Link/Workspace 明文。发送与接收共用这个闲置缓存上限，
它不是 Agent 总内存上限。UDP、配额、调度、流控窗口、认证和帧格式保持现有契约。

接收循环在首个 DATA 帧时取得一个 16 KiB 临时 buffer，并在该连接后续 DATA
帧之间复用；仅有控制帧或 UDP 的连接不会取得它。帧校验后，`handleLocked`
仍复制 DATA 至对应 Stream 的业务缓冲，再读取下一帧。UDP 队列和 PONG 等
控制帧保留独立 payload；公开 `ReadFrame` 仍返回由调用方拥有的数据。
读循环退出后才清零、归还临时 buffer。carrier failure 或 `Close` 不会提前
回收仍被读取操作引用的数据；`Close` 等待读循环退出。RESET 和迟到帧不会
让已接收的业务数据引用临时存储。每条实际接收 TCP DATA 的活动 Link 新增
最多 16 KiB 临时存储，断开时释放；这是降低逐帧分配的明确内存取舍。

## P3 按需状态通知

接收优化后的 mTLS profile 显示 `signalLocked` 占累计分配的 63.50%，因此
继续优化通知分配。Session 仅在业务操作检查状态、确实需要等待时创建通知
channel；检查与注册均持有同一 mutex。状态变化关闭当前通知并清除 Session
引用，所有该轮等待方都会醒来；即使关闭发生在进入 select 之前，通知也
不会丢失。下一轮等待建立新的 channel，不能消费旧事件。

没有等待方时，状态变化不分配 channel；carrier writer 的有界 `wake` 通知
仍发送，控制优先级、轮询公平性与队列容量保持现有规则。取消或超时后没有
额外等待方登记；至多留下一个未关闭 channel，下一次状态变化会关闭它。
不复用已关闭 channel，也不改变帧、鉴权、窗口、UDP 边界和 buffer 所有权。
回滚时恢复原先每次状态变化都建立新通知的实现并重启 Agent。
