记录；版本编号不代表发布。TST 发布默认值继续关闭。

## P3 缓冲区所有权

业务写入先复制到独占 buffer；入队前失败由 `send` 归还。入队后由队列或写循环
归还：RESET、规则关闭及 carrier failure 只回收仍在队列内的帧，已经出队且
正在写出的帧由写循环负责。调用方 deadline/cancel 先返回时不能提前复用。

缓存只保留最多 256 个 16 KiB buffer；满时丢弃。完整 buffer 在归还前清零，
防止较小帧尾部保留其他 Link/Workspace 明文。接收侧、UDP、配额、调度、
流控窗口、认证和帧格式保持现有契约。

## 2026-10-11 本机证据

宿主 Windows/amd64，i5-12500H；工具 Go 1.26.3（安装的 go 工具为 386，
本次通过 `GOARCH=amd64` 运行原生 64 位测试）。

```text
go test ./internal/securelink -run 'PooledPayload|PayloadPool' -count=20 -timeout=60s
go test ./... -count=1 -timeout=120s
go vet ./...
go test ./internal/securelink -run '^$' -bench '^BenchmarkTSTStream$' -benchmem -benchtime 500ms -count 5
```

前两项和 vet 已通过。基准以 `1e7bd43` 导出的源码和当前 pool + 清零实现
顺序运行，均为 amd64、同一负载与工具链。每操作分配约从 34.7 KiB 降至
18.3 KiB（约 47%），样本详见 [性能记录](protocol/tst-performance.md)。
本地脱敏样本/命令/源码 diff 摘要保存在 `scripts/perf/results/p3/`。

`GOARCH=amd64 CGO_ENABLED=1 go test -race ./internal/securelink` 已尝试，
因缺少 GCC 失败。Linux race、fuzz 和真实 shared-Link 验收由现有 CI 执行，
在当前候选收到成功结果前均保持待验证。

## 兼容和回滚

没有 API/数据库/ALPN/帧格式变更。TCP buffer 复用属于内部实现；回滚时恢复
原先逐帧分配并重启 Agent。重启遵循现有连接中断与 LKG 恢复语义，不承诺
无损会话迁移。发布容量、长稳和外部安全审查门槛保持单独验收。
