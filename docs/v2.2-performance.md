## P3 缓冲区所有权

业务写入先复制到独占 buffer；入队前失败由 `send` 归还。入队后由队列或写循环
归还：RESET、规则关闭及 carrier failure 只回收仍在队列内的帧，已经出队且
正在写出的帧由写循环负责。调用方 deadline/cancel 先返回时不能提前复用。

缓存只保留最多 256 个 16 KiB buffer；满时丢弃。完整 buffer 在归还前清零，
防止较小帧尾部保留其他 Link/Workspace 明文。发送与接收共用这个闲置缓存上限，
它不是 Agent 总内存上限。UDP、配额、调度、流控窗口、认证和帧格式保持现有契约。

接收循环在首个 DATA 帧时取得一个 16 KiB 临时 buffer，并在该连接后续 DATA
帧之间复用；仅有控制帧或 UDP 的连接不会取得它。帧校验后，`handleLocked`
仍复制 DATA 至对应 Stream 的业务缓冲，再读取下一帧。UDP 队列和 PONG 等
控制帧保留独立 payload；公开 `ReadFrame` 仍返回由调用方拥有的数据。
读循环退出后才清零、归还临时 buffer。carrier failure 或 `Close` 不会提前
回收仍被读取操作引用的数据；`Close` 等待读循环退出。RESET 和迟到帧不会
让已接收的业务数据引用临时存储。每条实际接收 TCP DATA 的活动 Link 新增
最多 16 KiB 临时存储，断开时释放；这是降低逐帧分配的明确内存取舍。

## P3 按需状态通知

接收优化后的 mTLS profile 显示 `signalLocked` 占累计分配的 63.50%，因此
继续优化通知分配。Session 仅在业务操作检查状态、确实需要等待时创建通知
channel；检查与注册均持有同一 mutex。状态变化关闭当前通知并清除 Session
引用，所有该轮等待方都会醒来；即使关闭发生在进入 select 之前，通知也
不会丢失。下一轮等待建立新的 channel，不能消费旧事件。

没有等待方时，状态变化不分配 channel；carrier writer 的有界 `wake` 通知
仍发送，控制优先级、轮询公平性与队列容量保持现有规则。取消或超时后没有
额外等待方登记；至多留下一个未关闭 channel，下一次状态变化会关闭它。
不复用已关闭 channel，也不改变帧、鉴权、窗口、UDP 边界和 buffer 所有权。
回滚时恢复原先每次状态变化都建立新通知的实现并重启 Agent。

## P3 有界控制帧环形队列

`266eb44` 的 mTLS profile 中，`queueControlLocked` 占累计分配的 14.85%。
控制队列原先通过切片头部出队，持续流量会反复分配新存储。本轮改为 Session
独占的环形队列：首次入队分配 8 个槽位，按需倍增至现有的 1024 帧上限；
排空后复用存储，出队立即清除槽位的 payload 与完成通知引用。正在写出的
请求按值移交给 writer，复用槽位、调用方取消或 session failure 都不能擦除
其 payload。Session 失败时清空剩余请求并释放槽位存储。

未使用控制队列的 Session 不分配槽位。在 amd64 上，空闲保留存储从 512 B
至最多 64 KiB/Session（不含 payload/channel）；这是减少逐帧分配的取舍，
不是 Agent 总内存上限。WINDOW_UPDATE 仍按 Stream ID 合并，满队列可合并
已有更新，但新帧被拒绝或等待；OPEN 的 ID 分配与入队仍持有同一把锁。
控制帧每八帧让出一次数据轮询，两级流控、FIFO、背压与完成通知语义保持现有
契约。回滚时恢复切片队列并重启 Agent，连接恢复遵循既有 LKG 语义。

## 六拓扑实际网络条件矩阵与持续负载收口

按用户决定，真机部署、固定 Linux 主机/真实 WAN、跨日长稳与独立审查推后，
待后续开发完成统一执行。本轮新增自动验收工具，不把这些延后项目标为通过。

`agent/internal/tstruntime/performance_test.go` 是 opt-in workload，正常单测仅
跳过该入口，不新增公开端点、运行时能力、第三方依赖或部署开关。
`scripts/perf/runtime-matrix.py` 编译独立二进制，覆盖 plain TCP/UDP、真实
`RELAY → EGRESS → target`、TST TCP/UDP、同 carrier 的 TCP/UDP 混合流；
64/1400/16384 字节、低并发/8 并发。Linux clean、20ms RTT、20ms/1% 丢包
三组共 108 个 case，所有 case 在新的 netns 内执行，宿主 qdisc 必须前后一致。
TST UDP 仍通过 TCP carrier，整形该 TCP 端口，原生 relay 只整形节点间 hop。

每个 case 使用逐包客户端/序号与完整 payload 校验，原始 RTT 分位数与吞吐
由 Python 独立复算；TST 各规则持久计量必须覆盖完成的双向 payload 字节。
工件保留实际 tc 命令、qdisc 初始/最终 JSON、分类器及包/丢弃计数，必须有
真实整形流量，丢包组必须观察到实际 drop；20ms 条件的观测延迟也须达到下限。
仅 plain UDP 在丢包条件允许超时，payload 损坏和 TST/native 错误仍失败。

持续负载每秒采集 goroutine/heap，Linux 另采 RSS/FD/CPU ticks，保留中途
进度收据与最终全部资源读数；每协议最多 10,000 个均匀 reservoir RTT 样本，
完成/错误计数完整保留。结束后必须持续一秒达到 goroutine/FD 回收阈值。
网络 poller 先初始化再读基线，避免将 Go 自身持久 epoll/eventfd 算作 case
泄漏。回显目标显式请求 4 MiB UDP socket 缓冲，仅影响测试 fixture；
Linux 实际容量仍受系统上限控制，不改宿主 sysctl 或生产 runtime。

首轮本机审计将 Windows 极短 RTT 的原始零值拒绝，修订后保留真实时钟读数，

`scripts/perf/results/runtime-local-matrix/`、`runtime-local-matrix-final/`。
最终矩阵与 600 秒本机混合流的结果以新收据为准，不覆盖失败记录。
