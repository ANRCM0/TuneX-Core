# ADR-0002: 执行授权、部署切换与实施契约收口

- 状态：Accepted（目标设计；尚未实现）
- 日期：2026-10-12
- 取代范围：ADR-0001 中“先实现 ADP/1”的实施目标；保留其 Forward First、Tiny Core、独立 Agent 和不兼容 V2 的决定。

## 背景

原基线明确了可靠性原则，但租约续期、跨启动报告排序、部署切换和 Operation 终态仍有多种解释。直接实现会导致 Control 与 Agent 各自补充不同语义。

## 决策

1. 新实现使用 [ADP/2](../protocol/agent-deployment-v2.md)。加入强制会话代次、快照摘要和直接驱动配置契约，属于安全相关协议变化，不能继续标记 ADP/1。ADP/1 文档保留为被取代的设计记录；V2 代码也不因此获得兼容性。
2. 配置不变的续期也产生更高 Snapshot generation；不可变快照不得原地延长 validUntil。相同 generation、不同摘要必须拒绝。Agent 以配置摘要与 deploymentGeneration 判断是否需要改变数据面，不能因续期重启连接。
3. 同一 Node 只承认一个当前 sessionEpoch。新启动通过 Hello 获得更高代次；旧代次报告不得推进当前状态。会话取代不被描述为远程立即断流，离线执行仍受旧授权截止时间约束。
4. 普通禁用/删除允许有界 drain；授权或凭据到期是硬截止，不允许借 drain 延长执行。进程重启后必须在线完成 Hello 并获取新快照，才可重建转发。
5. 下游须 active/ready 后才激活客户端入口。prepared 仅表示配置与资源计划已暂存，不表示数据通路已激活。
6. 监听器 slot 与 generation 下的已接入连接分开管理。旧连接可受控排空，但不再拥有 successor slot。切换失败须显式展示旧 applied 与新 desired，不自动改写用户意图。
7. Runtime 拥有 Operation、预留和清理任务；Application 用例组织共享数据库事务。所有权边界不等于独立数据库或跨服务事务。
8. 最小驱动能力校验提前至单节点阶段；不可变 Profile 与 Relay 数据面认证提前至双节点阶段。高级传输演进不能成为这些基本依赖的首次实现位置。
9. Core 的 ID/整数/主机名规范化在现有形状内收紧为可跨语言验证的规则；已接受的领域语义变化由本 ADR 记录。
10. 控制库恢复采用停发授权、等待旧授权耗尽、轮换信任与重新注册的保守流程；禁止清空 Agent high-water 以接受旧数据库版本。

## 代价与边界

续期会产生数据库写入和完整快照传输；容量测试必须包含此成本。旧快照清理不得删除防重放 high-water。在线重启要求降低了 Control 故障期间的恢复能力，但避免跨启动时钟与缓存授权歧义。后续如要支持离线重启，必须通过新 ADR 和故障测试。

默认时长与容量是开发基线，不是吞吐量承诺。安全审计、真实网络验收和发布门槛仍适用。本次仅修改文档、协议 Schema 与样例，不实施 API、数据库或 Agent。
