# ADR-0001: VNext 破坏性重构与规范重建

- **状态**：Accepted
- **日期**：2026-10-12
- **范围**：TuneX VNext 源码和正式架构文档

## 决策

TuneX VNext 不需要向旧 V2 的 API、Prisma Schema、Tunnel/Link 业务模型、Agent 命令接口及前端页面契约提供向后兼容。可以在同仓重建或启动独立项目；以最小转发闭环为首期目标。

当前仓库旧的架构、协议、进度、运行手册和测试说明全部退出“当前规范”身份；工作树中的旧文档在本次变更被移除，用新版权威文档替代。旧文档仍可从 Git 历史检索；保留历史第三方来源及许可证归档的法定义务，不属于产品规范兼容要求。

本次变更**只更新文档，不宣称已迁移旧代码或数据库**。历史程序运行风险、数据备份以及安全授权约束仍然存在，不得因“破坏性重构”忽略。

## 理由

维护两套业务实体、两套控制协议和历史迁移兼容层会破坏 Tiny Core 目标。目标是先冻结 Core/Forward/Assignment/Snapshot 契约，再实现正确的单节点 TCP/UDP 真实闭环，最后增加模块能力。

## 长期准则

- 以 Forward 为唯一必选业务对象、Node 为基础执行资源。
- Core 不持有 IO；Application 负责业务所有权；Runtime 负责部署；Agent 负责数据面。
- 从 VNext v1 开始，变更跨组件协议必须版本化且有兼容/拒绝策略。
- 无法通过真实集成/实网验收之前不得发布“VNext 可生产运行”声明。
