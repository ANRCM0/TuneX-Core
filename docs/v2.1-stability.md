# TuneX V2.1 Stability Worklog

This worklog tracks the first V2.1 slice from the follow-up development plan.
V2.1 changes remain compatible with the V2.0 data model and keep TST disabled
by default until the existing release gates pass.

## S2/S4: control-plane outage backoff

The Agent control client now uses a bounded exponential retry delay after a
failed command pull: 1s, 2s, 4s, 8s, 16s, then 30s. A successful pull resets
the streak. The wait is timer-backed and context-cancellable, so shutdown does
not wait for the full outage delay and repeated failures do not accumulate
`time.After` timers.

The backoff only changes control-plane polling. Runtime listeners, leases,
configuration fences, acknowledgements and reconnect reconciliation keep their
existing semantics. An unreachable panel therefore does not trigger a data
plane downgrade or a plaintext fallback.

## S1: credential lifecycle and rotation boundaries

TST credential bundles are now validated before a placement is compiled. The
Panel checks the private Link CA, the CA signing relationship, leaf-to-private
key matching, exact Workspace/Link/node/role URI SANs, the opposite peer URI,
the DNS SAN and the shared expiry boundary. A malformed or cross-Link bundle is
rejected with `invalid_tst_credential` before it can reach an Agent.

Expiry handling is explicit and independent from the placement lease:

- `active` credentials are reused;
- credentials inside the 24-hour renewal window trigger a new generation and
  fresh CA/key material;
- `expired` or malformed credentials fail closed for new placements;
- expired material remains readable on removal-only paths so revocation can
  finish and persist its tombstone.

The generated certificate lifetime remains seven days, and rotation continues
to use generation replacement. Existing sessions are bounded by the Agent's
certificate and lease timers; this change does not introduce plaintext fallback
or online OCSP claims.

The next V2.1 slice is explicit failure-injection coverage for reconnect, lease
expiry, configuration rollback and orphan cleanup, followed by the Linux race
and long-stability gates that remain environment-dependent.
