# FR-0039: Controlled Forward Path Echo

Date: 2026-10-24. Status: source-authorized; acceptance unexecuted.

The human's P task and standing foundation source authorization permit this
serial extension. L2 codecs/native listener adapters and L3 Probe planning consume
original Node authorization, Relay assignments, published Runtime snapshots,
Probe permits and original execution tickets. L0 and execution authority do not
change. No parallel module or verification gate is opened.

Add tcp-path-echo-v1/udp-path-echo-v1, point agent-local-forward-ingress, and
probe.tcp-path-echo.v1/probe.udp-path-echo.v1. The explicitly enabled v4 extension
negotiates seven measurements; the legacy five remain valid and unchanged. Old
closed readers refuse the extension. No silent Direct downgrade is permitted.
Path capability is checked on every current planner/permit validation, not saved
as a renewable qualification. Original Echo qualification and original instance
expiry/revocation remain necessary. New SQL migration expands retained measure
enums without rewriting results, permits or protected Agent history.

The planner reuses Relay's original publishable assignments and authorizes every
node through the public Node owner in the supplied transaction. Every published
active assignment must match the current route/revision/config/fence. Agent
resolves its own current ingress listener and rechecks original ticket/socket
identity. Signed nonce proof binds the controlled final endpoint to the permit.
This observes the whole forwarding path from its local ingress, not public
internet reachability or arbitrary application health. Original payload budgets,
UDP association lifetime, hard deadlines and claim/result owners still apply.

Compatibility: existing constructor arguments keep defaults; path issuance and
Agent capability default off. Consumers opting in must upgrade Control, Agent,
closed DTO readers and SQL first. Partial deployment refuses path work; legacy
Direct v1-v4 remains available. No new engine, ledger, scheduler or quota owner.

Actions repair: path listener observation uses the explicit L2
`nativeexecution.PathProbeIngress` adapter after the original host checks. It is
not installed as the legacy Direct Probe hook on Relay/Multihop descriptors;
their old registry port/capability agreement and five-measurement advertisement
remain unchanged. The separate path opt-in advertises the new path capabilities.

Planned acceptance: distinct TCP/UDP descriptors and signed frames; legacy five
versus extended seven; disabled/missing capability; Direct/path mismatch; all
node grants/sessions/credentials; prepared/draining/mismatched snapshots; route
changes during claim/status/result; original once-only consumption; actual local
listener changes; namespace and independent-host forwarding separately. Source
cases are authored with the implementation; no execution is claimed.

Integrated source counters: Probe module5/owner3/machine3, Forward command4 and
capability3, Control HTTP6/detail4/startup3, Agent CLI2/command2/nativeexecution3.
FR-0040 subsequently adds Probe history module3, Station module3/API4 and the
0046/UpgradeAssessment10 cumulative successor. Earlier slice counters/profile
ceilings are historical changes, not current accepted interfaces.
